## 1. Identity & Purpose

**LAMDEX** = *Lateral Active-Movement Detection eXercise*. A web-based, self-contained security lab that:

1. **Simulates** MITRE ATT&CK **lateral movement** in an isolated AD topology (`corp.local`,
   hosts DC01/FS01/WK-*/ATK01/NSM01), generating **ground-truth-labeled** telemetry records.
2. **Detects** with a declarative rule store (Sigma-style fields) over that telemetry, using
   `p_detect` (false-negative sampling) and `p_fp` (false-positive sampling) to model imperfect detection.
3. **Scores** detection quality: per-technique + overall **precision / recall / F1**, plus technique
   **coverage**.
4. **Reports** in `.xlsx` · `.xls` · `.csv` (bundle) · `.html`, all with **SHA-256 evidence chains**,
   mapped to ISO 27001 / NIST CSF & 800-53 / OWASP Top 10 / MITRE ATT&CK.

V1 = **simulator-grade** detection engineering instrument (not a real EDR, not real AD). Web console + headless CLI.
All output stamped `is_lab:true` / `LAB:true`.

## 2. Vocabulary (speak consistently)

| Term | Meaning |
|------|---------|
| record | one simulated telemetry item: `observable`, `event_id`, `data_source`, `fields`, `is_benign`, `technique_id` |
| observable | short tag of a detectably interesting event, e.g. `admin_share_access`, `svc_create`, `tgs_rc4` |
| step | one ground-truth step of a technique = one record generated by `engine._step_record` |
| benign record | synthetic harmless noise (`benign_admin_logon`, `scheduled_job`, `patch_service`, `rdp_console`) |
| run | one technique execution: `run_id = r<yyyymmdd_hhmmss>_<TECH>` + records + sha256 |
| detection | row emitted by `evaluate_run` for a matched rule; `tp`/`fp` booleans relative to run technique |
| rule | declarative dict: `id, name, level, technique (or None=behavioral/generic), observables{}, event_ids{}, source, p_detect, p_fp, desc` |
| p_detect | probability a matched technique rule actually fires (models imperfect detection → FN) |
| p_fp | probability a matched **benign** record triggers a generic rule (models noise → FP) |
| coverage | covered / expected rule count per technique (rule store vs a technique's rules) |
| MSS / SBS | (internal) detector split — not used; keep scoping to observables |

## 3. Architecture In One Breath

```
web console (Flask, templates) 
  → POST /techniques/run  → engine.run_technique(tech, rng)     # telemetry + benign noise
  → rules.evaluate_run(run, rng)                                 # sampled detections
  → store (SQLite: runs, detections, lab_state, reports, audit)
  → metrics.compute(runs, detections)                            # precision/recall/F1 per+overall
  → report.write_bundle → .xlsx (6 sheets) · .xls · .csv×5 · .html  (SHA-256 each, registered in DB)
```

- **Storage:** `sqlite3` stdlib, `WAL` on, single file `out/lamdex.db`. Never rename columns without
  updating `store.list_*` mappers AND `report` sheet column lists (all positional).
- **RNG:** `random.Random(time.time_ns())` passed through `main`/CLI → `run_technique` (O1 in state.md
  wants seed-based reproducibility).
- **Reports dir:** `out/reports/`; CSV written `utf-8-sig` (Excel friendly); `.html` embeds inline CSS only.

## 4. Key Coding Conventions (MUST follow)

1. **No eval/regex in rule matching** — `rules.rule_matches` compares sets (`observables`, `event_ids`,
   `data_source`). This is a security control (see security.md T4).
2. **HTML output always escaped** — `_hl()` (`html.escape(quote=True)`) in `report.py`; Jinja
   autoescape ON in templates. Never add `<script>` or CDN (CSP `default-src 'self'`).
3. **SQL parameterized everywhere** — never f-string SQL with user input (`store.py`).
4. **Metrics positionality** — `metrics.technique_metrics` keys are
   `expected, covered, tp, fp, fn, precision, recall, f1`. Do **not** rename `covered`→`coverage`
   again; three export sites already burned on that (xlsx, xls, csv).
5. **Auth gate on all routes** — new endpoints must sit behind `before_request::gate()` and be
   audit-logged (`storage.audit(actor, action, detail)`).
6. **Sim vs reality discipline** — never remove `is_lab`/`LAB:true`; detection rows carry both `tp`
   and `ground_truth_match`.
7. **No comments in code unless explicitly requested** (team rule); self-document via names + reservation docs.
8. **`export_html` uses token `.replace()` templating**, NOT `%` or `.format()` — CSS contains literal
   `%` and `{}` that break those formatters (gotcha below).

## 6. Gotchas & Lessons (hard-won this session)

1. **`export_html` broke with `%`-formatting** — CSS contains `height:100%` and `{}`; the `%` operator
   raised `unsupported format character ';'`. Fix: token-replace templating (`__X__` + `.replace`).
2. **Formatting precedence** — `"DET-%06d" % uuid.uuid4().int % 1000000` parsed as `(str % int) % int`
   and raised `TypeError`. Parenthesize the modulo: `"DET-%06d" % (uuid.uuid4().int % 1000000)`.
3. **Metric key renamed mid-session** — `covered`/`coverage` mismatch caused 3 distinct KeyErrors
   (xlsx, xls, csv exporters). Keep one canonical key per metric family; grep all exporters on rename.
4. **Overlap FP is by design** — SMB admin-share (`T1021.002`) trips the PsExec rule (`T1543.003`)
   because both use `svc_create`; DCOM/WMI share `dcom_connect`. This is the *tuning lesson*, not a bug.
5. **`storage` is module-global in `main.py`** — tests reuse it; a fresh dataset requires deleting
   `app/out` before `--run-demo-only` (or the DB accumulates runs across attempts).
6. **`xlwt` has no `__version__`** — attribute check raised AttributeError during env probe; import
   behaviour is fine, don't gate on a version attr.
7. **Generic (behavioral) rules must only fire on `is_benign` records** — `evaluate_run` enforces
   `rec["is_benign"] and rng.random() < rule["p_fp"]`; otherwise tech-overlap floods FP (initial p_fp
   0.5/0.4 → precision 0.365; tuned to 0.12/0.15 → 0.39 hold).
8. **Do not write via Write tool without JSON-escaping `\`** — code strings like
   `r"C:\Windows\ADMIN$\PSEXESVC.exe"` must be escaped as `\\` in tool payloads; past hiccups truncate writes.
