## 1. What exists now

A portable, **non-executing** GUI workbench that implements the safe slices of `architecture.md`:

- **Intake & quarantine vault** — SHA-256 hash-first, dedupe, immutable hash-named blobs.
- **Static analyzer** — whole-file/block entropy, string extraction, minimal PE parse, crypto & ransom indicators.
- **Encryption-pattern engine** — pattern classification (full-file / format-preserving / high-entropy / no-signature), algorithm suspicion, key-handling hints, optional evidence-pair (original vs. .enc) comparison, confidence + risk flag.
- **Report generator** — Markdown + JSON, schema `sba.pattern.v1`, environment fingerprint.
- **Audit ledger** — hash-chained JSONL, `verify()` built in.
- **GUI (Tkinter, dark theme)** — Dashboard / Intake && Analyze / Reports / Audit Ledger / Settings && Security tabs.

### Architecture mapping (implemented here)
`6.1-6.2` intake+vault · `6.4` static · `6.5` pattern detector (structural only) · `6.6` reports · `15.2` ledger. **Not** implemented: Zone-0 detonation (7), web/API (6.7), repo collection (6.1 remote), SSO/RBAC (11).

## 5. How to use

**Run the exe (no install):**
```
dist\RansomLens.exe
```

**Run from source:**
```
python src\run.py
```

**Generate demo fixtures:**
```
python tools\make_fixtures.py      # writes under ./fixtures
```

**Workflow in the app:** Dashboard → Intake && Analyze (Add Files/Folder) → optional Evidence original → Scout (static preview) → Analyze → Reports (open/export) → Audit Ledger (verify chain).

**Rebuild:**
```
.\build.ps1                         # -> dist\RansomLens.exe
```

## 6. Known limitations / caveats

1. **No live detonation** — pattern classes are structural/statistical; exact algorithms are never claimed ("suspected"/"consistent" wording is deliberate).
2. Single-file evidence analysis only per job; full multi-file coverage/traversal metrics require the Zone-0 telemetry pipeline (architecture.md §7.3).
3. Minimal PE parser (format/import-hint level) — no disassembly; heavy RE is intentionally out of scope.
4. Modes like `format-preserving-encryption` require printable-header + partial entropy; tuned for common wrappers, not exotic containers.
5. 128 MiB/file cap protects memory; very large corpus analyses are run per-file.
6. No remote collection feeds (vetted hashes pull from public repos remains future work per architecture §19).
