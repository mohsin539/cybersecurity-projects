01

Executive Overview — Problem & Purpose

Why does a "check-in jitter and sleep study" matter? Every fleet of agents (IoT sensors, EDR endpoints, telemetry beacons, heartbeat pollers) risks the Thundering-Herd problem: when all agents tick on the same cadence, the server is hit by synchronised spikes.

Thundering-Herd Problem

1,000 agents sleeping 60s and waking at the same 60s boundary → 1,000 simultaneous requests → CPU/latency spikes, dropped packets, snowball retries that amplify the burst.

  • Un-correlated traffic peaks by 10–100×
  • Retry-storms during outage recovery
  • Hard-to-size infrastructure

Jitter — the Fix

Add a random offset (±Δ) to each agent's schedule so check-ins spread uniformly across the window. Traffic flattening replaces spike-flooding.

  • Uniform, Gaussian, Poisson & truncated-exponential samplers
  • Deterministic seeds for reproducible experiments
  • Configurable jitter % of base interval

Sleep — Duty-Cycling

Agents enter deep-sleep between check-ins (power-down radios, timers). Balances freshness of data against battery & bandwidth.

  • Fixed, adaptive & random sleep windows
  • Wake triggers, watchdog liveness
  • KPI: duty-cycle %, power budget, staleness

Study Objectives

  • Quantify herd-coefficient / load-spike factor per strategy
  • Compare jitter distributions statistically (Mann-Whitney U, Welch t-test, effect size)
  • Model power draw & network bytes vs. data freshness trade-off
  • Produce reproducible, auditable reports (.xlsx/.csv/.html)

Key Deliverables

  • Deterministic simulation engine (DT-sim, wall-clock optional)
  • Interactive CLI + TUI dashboard (rich)
  • One-click report bundle with embedded charts
  • Signed portable .exe, zero-install, no admin rights

Measured KPIs

  • Peak-to-mean request ratio & 99.9th latency
  • Bucket coefficient-of-variation (uniformity)
  • Sleep/wake duty-cycle & simulated mAh draw
  • Bytes/agent/day & sync-loss episodes

End-to-End Study Data Flow

The pipeline: profile → simulate → score → aggregate → render → package. Every stage is deterministic (seed-carried) and appended to an immutable audit log.

Check-in Lifecycle

SLEEPING ──► WAKING ──► CHECK-IN ──► PROCESS ──► SLEEPING

  • Wake decision: timer expiry + jitter offset
  • Check-in: request latency modelled by server queue
  • On failure → exponential backoff + fresh jitter
  • Heartbeat ~ keepalive from a subset of agents

Server-Side Model

  • M/M/c-style queue with configurable workers
  • Per-request service time distribution
  • Queue length & 99.9th percentile latency per bucket
  • Kernel-buffer drops at extreme synchronisation

Determinism & Replays

  • numpy.random.SeedSequence per scenario × replicate
  • Same seed → byte-identical results
  • Replay flag re-runs last seed registry
  • Config hash logged for reproducibility audits

The Jitter & Sleep Engine

The research heart. Jitter shapes when agents act; sleep shapes how often and for how long.

Jitter Distributions

StrategySamplerUse case
uniformU(−J, +J)Default; dead-simple spread
gaussianN(0, J/3)Natural sensor drift, mild clustering
triangularTri(−J, +J)Weighted toward nominal interval
poissonExp(λ) arrivalsRandom-slot / slotted ALOHA style
exp-truncatedExp clipped [0, J]Burst-then-quiet, aggressive de-sync

Jitter bound J = interval × jitter_pct / 100, clamped to a live global window so the herd-coefficient stays measurable.

Sleep Strategies

ModeBehaviourPower avatar
fixedConstant sleep windowBaseline reference
randomSleep × U(0.5, 1.5)Mixes duty cycles
adaptiveExtend after quiet roundsAligned with server backpressure
burst+backoffRetry storms with exp backoffStress / failure scenarios

Each agent carries a power profile (active mA vs. sleep µA) → simulates mAh draw and battery-life impact per strategy.

Study Orchestrator & Metrics

Turns a scenario card into a validated, replicated, statistically-scored study run.

1 · Load

Parse YAML/JSON scenario; schema-validate (pydantic)

2 · Normalise

Bounds-check ranges, clamp jitter %, resolve defaults

3 · Matrix

Build experiment grid + Latin-square ordering

4 · Replicate

SeedSequence → N runs per cell (default ×10)

5 · Aggregate

Pool KPIs, bootstrap CIs, run comparisons

6 · Publish

Render xlsx/csv/html, hash, write audit entry

Scenario Card (example YAML)

agents: 10000
interval_sec: 60
jitter_pct: 25
jitter_type: uniform
sleep_mode: random
sleep_base_sec: 45
run_length_sec: 3600
replicate: 10
seed: 42
server:
  workers: 50
  service_ms: 8
power:
  active_ma: 35
  sleep_ua: 900

Key Metric Equations

  • HerdCoef = peak_bucket / mean_bucket
  • Uniformity = 1 − (std / mean) over buckets
  • DutyCycle = active_s / total_s
  • Power = (mA·act + µA·slp) · hrs / 1000 → mAh
  • p99.9 Latency from server queue tail

Scoring & Verdicts

  • Statistical Win: Mann-Whitney U p < 0.05 (Bonferroni-corrected for grid)
  • Practical Win: Hedges' g ≥ 0.5
  • Traffic Win: <1.05-spike plateau achieved
  • Final verdict per strategy: PASS / CAUTION / FAIL

Risk Register

  • AV false-positives → signing + clean-room builds
  • PyInstaller hidden-import drift → pinned hiddenimports
  • Numerical determinism across libs → pinned lock + LAPACK matrix lock

  • Pass static-analysis gate with 0 critical findings
