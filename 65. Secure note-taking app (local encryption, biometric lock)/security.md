# 🛡️ Security Model — SecureNote Pro (implemented)

> Status boundary: one write-ahead, hash-chained **audit ledger** log file is kept
> **HMAC-signed + encrypted**; one vault file keeps all note content encrypted.
> No cloud, no telemetry, no network egress by design.

---

## 1. What was actually built (evidence-based)

| Security layer | Implementation in this repo | File |
|---|---|---|
| AEAD cipher | AES-256-GCM (96-bit nonce, 128-bit tag), per-note + whole-vault envelopes | `src/secure_note/crypto_core.py` |
| Passphrase KDF | Argon2id (`m=64 MiB, t=3, p=4`), salt 16B + fixed app pepper | `crypto_core.py` |
| Sub-key expansion | HKDF-SHA256 domain separation (DEK, MAC, verifiers) | `crypto_core.py` |
| Authenticated unlock | passphrase verifier + KEK verifier (constant-time compare) | `vault.py` |
| Biometric unlock | Windows Hello `UserConsentVerifier` (WinRT) gating BK release | `auth.py` |
| Device binding | BK sealed under DK; DK stored via **DPAPI** (device+user bound) | `dpapi_binding.py` |
| Rate limiting | Exponential backoff 5→30→120→600 s per slot; 10 failures → hard lockout | `auth.py` |
| Secure wipe | Overwrite with CSPRNG noise + fsync + delete (vault & dk) | `vault.py` |
| Audit integrity | SHA-256 hash chain + HMAC (audit key, DPAPI-bound); AEAD-encrypted file | `audit.py` |
| Report signing | ECDSA P-256 over manifest; DPAPI-wrapped signer key | `report.py` |
| Compliance engine | Live control→evidence mapping (ISO 27001, NIST CSF 2.0, OWASP Top 10) | `policy.py` |

## 2. Key hierarchy (as operated)

```
passphrase ──Argon2id→ KEK ──AEAD wrap──▶ dek_wrapped (DEK)
biometric ──gates──▶ BK ──AEAD(DK,BK)──▶ bio_blob     (BK device-bound via DK)
DK ──DPAPI──▶ dk.bin                    (device+user root of trust)
DEK ──AEAD──▶ body (notes list; each note its own AEAD envelope)
AK ──DPAPI──▶ audit.key                 (HMAC key for the ledger)
```

- KEK/DEK/BK exist only in RAM while unlocked; **zeroized on lock** (`Vault.lock`).
- Lockout threshold destroys the vault + keys (`wipe`).

## 3. Threat model recap (STRIDE, verified behavior)

| Threat | Verdict | Verified by |
|---|---|---|
| Spoofing (stolen passphrase) | 2FA biometric gate + backoff | selftest lockout branch |
| Tampering (edit notes/audit) | AEAD tags + hash chain + HMAC | `audit_verify()` PASS |
| Repudiation | signed, chained events | report `SIGNATURE.json` |
| Disclosure (device theft) | plaintext-at-rest absent; DPAPI binds to user | file dump shows ciphertext only |
| DoS (unlock spam) | exponential lockout / FAIL-closed | smoke test assert |
| Priv-elevation | fail-closed vault; no admin surface | code-level |

## 4. Known limitations (be explicit in reports)

- **Biometric gating is advisory**: BK is encrypted with DPAPI-DK, so an attacker
  with the same Windows user session + code execution could bypass the Hello dial
  by calling `unlock_with_biometric` directly. Mitigation: hardening moved to a
  real Secure Enclave/TPM seal (roadmap) — Windows Hello "strong" verification +
  `CredentialUnlock` marker can close this.
- DPAPI is only as strong as the user's Windows login & local storage; on machines
  without a TPM the user master key is software-protected.
- Audit log stores event metadata (actions/timestamps) in a readable-after-keys file;
  confidentiality of the log relies on the AEAD file encryption (present).
- FIPS-mode is NOT asserted (uses validated `cryptography` primitives but not
  a FIPS-validated binary).

## 5. Compliance posture intent

Implementations map to: **ISO/IEC 27001:2022 A5.15/A8.2/A8.24/A8.26/A8.27/A8.10/A8.16**,
**NIST CSF 2.0** (PR.DS-1/6, PR.AA-1, PR.PS-1, DE.CM, RS.RP, RC.RP), **OWASP Top 10**
(A02/A07/A08/A09; A10 eliminated architecturally). Live scores are generated by
`policy.score()` and exported via the Reports tab.
