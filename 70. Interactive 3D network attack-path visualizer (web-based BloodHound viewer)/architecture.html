Solution Overview

What the platform is, who it serves, and the value it delivers across the security lifecycle.

Problem

BloodHound's flat 2D graphs collapse at scale — 100k+ nodes become unreadable. Analysts cannot intuitively see which shortest privilege path a threat actor would exploit, nor quantify blast radius.

Solution

A WebGL-powered 3D graph universe with depth-as-risk, glow-as-criticality, edge-flow animation for attack chains, semantic zoom, and one-click path replay from Tier-0 crown jewels back to attacker seed nodes.

Outcome

Mean time-to-insight reduced from hours → seconds; board-ready risk reports; evidence-grade audit trails proving control effectiveness for ISO 27001 / NIST audits.

02

Design Principles

Guiding engineering and security axioms that shape every decision in the blueprint.

Secure by Design (P-01)

Threat-model first (STRIDE per component). Security is a build artifact, not a bolt-on — mapping directly to ISO A.8.26 OWASP A04.

Zero Trust Data Access (P-02)

Every graph query is re-authorized server-side against the caller's ABAC policy — no client-side graph filtering, no shared service accounts.

Defense in Depth (P-03)

Seven concentric control layers: perimeter → network → host → app → data → cryptographic → governance.

Least Privilege & Separation of Duties (P-04)

RBAC roles + ABAC attribute rules; report authors ≠ report approvers; auditors hold read-only immutable views.

Everything is Evidence (P-05)

Every read of a sensitive node, every export, every admin action lands in a hash-chained, WORM-tiered audit ledger.

Scale without Degradation (P-06)

Level-of-detail culling, instanced GPU rendering, server-side path pre-computation, query budget ceilings per tenant.

05

Component Deep-Dive

Each microservice with its responsibility, interfaces, security controls, and scaling model.

Auth & Identity Service SEC

  • Role: OIDC login via Keycloak, TOTP/WebAuthn MFA, short-lived JWT (15 min) + refresh rotation, session vault in Redis
  • Interface: /oauth2/*, /introspect, JWKS endpoint
  • Controls: account lockout (5 attempts / 15 min), passwordless preferred, device fingerprint binding, anomaly re-auth
  • Maps to: ISO A.5.17 · A.8.5 · NIST PR.AA-01/03 · OWASP A07

Graph Query API CORE

  • Role: Serves node/edge/subgraph slices; only entry point to Neo4j for clients
  • Interface: GraphQL (persisted queries only — no arbitrary client Cypher) + REST fallback
  • Controls: parameterized Cypher builders, query cost budget, row/depth caps, per-tenant isolation, result redaction
  • Maps to: ISO A.8.26 · NIST PR.DS-05 · OWASP A01/A03

Path Analysis Engine CORE

  • Role: Computes attack paths: unweighted BFS, Dijkstra, Yen's k-shortest, cycle detection, Tier-0 reachability matrix
  • Interface: gRPC ComputePaths(src, dst, k, filters); async jobs via Redis Streams for large domains
  • Controls: execution time ceiling (2 s), memory governor, deterministic result cache keyed by graph version hash
  • Output: path objects with per-edge risk, ATT&CK technique, remediation hint

Ingestion Service DATA

  • Role: Accepts SharpHound ZIP / AzureHound JSON / BloodHound API pulls; validates, hashes (SHA-256), virus-scans, normalizes, upserts
  • Interface: POST /ingest (mTLS or signed JWT), scheduled pull connectors
  • Controls: collector certificate pinning, file size ≤ 512 MB, JSON schema strict mode, quarantine on anomaly
  • Idempotency: content-hash + collection timestamp prevents duplicate merges

Policy Engine (OPA) SEC

  • Role: Centralized ABAC decisions: who may see which OU/domain/tagged data; export permissions; report scopes
  • Interface: POST /v1/data/ps3d/allow (sidecar, <5 ms)
  • Controls: Rego policies in Git (versioned, peer-reviewed, 4-eyes release), decision logging to audit ledger
  • Maps to: ISO A.5.15/18 · A.8.3 · NIST PR.AA-05 · OWASP A01

Notification & Workflow OPS

  • Role: Publishes "new critical path" events; drives approval workflows for exports above classification threshold
  • Interface: Redis Streams → SMTP / Slack / Teams / webhook (SOAR)
  • Controls: outbound allow-list only (anti-SSRF), templated payloads (no raw graph data in email), rate-limited digests
  • Maps to: NIST DE.CM-09 · RS.MA-02 · ISO A.5.24–5.26

Security Architecture — Defense in Depth

Seven concentric defense layers with ownership, plus the cross-cutting identity/ABAC control plane.

Trust boundaries: internet → WAF (TB-1) · WAF → gateway (TB-2) → services (TB-3, mesh mTLS) → data (TB-4, private VPC) · collector → ingestion (TB-5, mTLS). Every boundary terminates TLS, authenticates the caller, and emits an audit event.

Comprehensive Reporting Subsystem

From live graph state to signed, board-ready evidence — templated, scheduled, and access-controlled.

Report Types CORE

  • Executive Risk Summary — board-ready PDF with risk trend, top-5 paths, heatmaps
  • Technical Attack-Path Dossier — full path sets, each edge with technique + remediation
  • Tier-0 Exposure Matrix — every principal able to reach Domain Admins / crown jewels
  • Compliance Evidence Pack — control → artifact matrix (ISO/NIST/OWASP)
  • Delta / Drift Report — what changed since last collection, new risky edges
  • Audit Trail Report — user actions, logins, exports over a date range

Rendering & Distribution

  • Jinja2 templates → headless Chromium PDF, plus CSV/JSON/HTML/STIX 2.1 exports
  • Scheduling: cron daily digest · event-driven on new critical path · on-demand
  • Delivery: email, portal, S3 presigned URL, REST download, SOAR handoff
  • Every artifact Ed25519-signed; public /verify page validates integrity
  • Attribution: author + approver recorded; watermark + expiry TTL for classification

Approval Flow

Reports ≥ "confidential" require 4-eyes sign-off before release; audit pinned to decision.

Versioning

Every run snapshot versioned; historical reports reopenable with graph-version hash.

Retention

Regulatory schedule: 7 y legal · 3 y audit pack · 30 d drafts, then WORM purge job.

Access

RLS-scoped rows; downloadable only by role + ABAC scope + one-time tokens for link.

12

Audit & Assurance Subsystem

An immutable, hash-chained ledger proving who did what, when, and on which graph object — engineered for evidentiary trust.

What is Audited

  • Logins, MFA challenge, lockout, logout, passwordless registration
  • Every graph query execution (actor, object IDs, scope)
  • Path computation requests + path exports / report downloads
  • Ingest uploads (content hash, collector, schema version)
  • Policy (Rego) changes, role grants/revocations, admin & break-glass actions
  • Config, key rotation, retention purge operations

Event Schema + Integrity

  • Canonical: {event_id, ts, actor, role, action, object_type, object_id, tenant, ip, ua, mfa, prev_hash, hash, meta}
  • Each row stores hash(prev_hash || payload) — chain tamper-evident
  • Nightly chain-verify job re-computes chain + Merkle root anchor; any break → P1 alert
  • Append-only DB triggers reject UPDATE/DELETE on ledger tables
  • SIEM stream (CEF/JSON over TLS) for SOC correlation & alerting
  • Cold archive to S3 Object Lock (WORM) — A.5.33 evidence retention

Anomaly Engine

Baseline mass-export volume; flags off-hours Tier-0 reads, unusual query shapes, burst exports.

Auditor Role

Read-only immutable view; cannot edit/export raw chain without 4-eyes approval.

Evidence Bundles

ISO A.8.15 / A.9.2-style bundles: timeline, hash-chain proof, report artifacts.

Retention

12 mo online · 24 mo archive · 7 y for security events; immutable throughout.

Report integrity chain: report artifact (SHA-256 + Ed25519 signature) is itself referenced by an audit event whose hash is chained into the ledger — a tampered report breaks the chain, an erased chain fails verification, and both are SIEM-alerted. This delivers court-ready, audit-gradable evidence.
